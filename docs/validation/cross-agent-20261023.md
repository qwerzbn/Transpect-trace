# 跨 Agent 多步骤传播：2026-10-23 实现与验收

本阶段在既有 `release` 工作树上扩展 Flow，使用两个固定行为的测试 Agent 验证查询、委派、转换、最终外发。文件和 Named Pipe 两条原受控链路保持[阶段性完成](cross-application-20261023.md)；整个跨应用模块仍未全部验收。

本轮没有接入真实 Agent 框架、生成式摘要模型、数据库或邮件系统。测试 Agent 通过已登记 Python 解释器独立运行；本地 JSON 查询代表数据读取，Named Pipe 携带任务及消息 ID，B 调用 WinHTTP 工具上传到不转发流量的 localhost HTTPS 服务。全部新增能力 `can_enforce=false`，实际阻断数为零。

## 交付

- `flow/agents`：受控多步骤运行器、严格消息协议、Agent 身份与传播证据模型、只读报告。
- `ttrace flow agents run/status/report`：与原 `flow`、`guard`、`observe`、`protect` 命令兼容。
- 4 份独立版本化 Schema：Agent 会话、消息观察、传播关系和实验清单；原有 30 份 Schema 保持不变。
- 同步 Named Pipe 测试 Agent A/B、正常验证证书的 WinHTTP HTTP/1.1 上传工具、五场景重复实采探针。
- 原 Flow 增加可选的受限内存传输回调；不修改 FIO1、ECW2、Guard v1 和 UnifiedLLMRequest v1。

新清单固定基础解释器及所有本地参与程序导入脚本。受控启动使用 `-I -S -B`，禁用全局 site 启动逻辑并避免写 bytecode。先核验 A/B 实际 PID＋创建时间＋映像哈希，再等待 Native I/O、ETW、eCapture 就绪；B 管道 ready 后才释放 A。提前 terminal、丢失、身份不匹配及清理失败均保留缺口。

## 本轮真实实采

证据目录：本地忽略的 `runs/cross-agent/20261023-integration-01/`。实验时间：2026-10-23 15:05:46–15:06:56（Asia/Shanghai）。五种场景各重复三次，**15/15 通过**，没有剔除失败尝试。

| 场景 | A 读取 | A→B 消息 | B 外发 | 实采结论 |
| --- | --- | --- | --- | --- |
| 原文复制 | 含假凭据及登记文本 | 敏感内容保留 | 敏感内容保留 | 3/3：检测命中，TLS 与源站一致 |
| JSON 嵌套 | 含假凭据及登记文本 | 敏感内容保留 | 内容置于嵌套 JSON | 3/3：结构变化后仍命中 |
| 确定性摘录 | 含假凭据及登记文本 | 敏感内容保留 | 中文摘录保留凭据和登记文本 | 3/3：文本格式变化后仍命中 |
| A 只委派普通字段 | 敏感读取事实保留 | 仅普通内容 | 仅普通内容 | 3/3：委派及外发 no_match |
| B 只上传普通字段 | 敏感读取事实保留 | 敏感内容保留 | 仅普通内容 | 3/3：消息命中，最终外发 no_match |

9 个敏感外发正例均命中假凭据和登记文本；6 个负例未被误判为敏感外发。每组各有一个实际 Native 源读取、消息写入和消息读取观察，以及一个实际 eCapture 完整 HTTP 请求。逐次核对 TLS 正文和源站的同层哈希、字节数及次数，不使用哈希集合去重。

A/B Native I/O、ETW 和 eCapture 共 60 份健康记录，均有 ready/terminal、已验证身份，丢失和错误为零。默认产物秘密扫描通过；显式假数据输入单独排除并保留用于复现。测试证书租约清理成功。实验使用原 Flow Native 构建与 eCapture v2，没有把旧 C 上传程序的结果替代为新 Python WinHTTP 路径认证。

独立复核记录为同目录 `independent-review.json`，逐条校验 60 条 Agent 观察、243 条 Schema 记录、实际 Native／TLS 事件引用和回执多重集；没有遗留复核问题。独立扫描 240 个默认审计文件未发现测试秘密，探针扫描包含外围清单等文件共 261 个，同样通过。另行查询确认 30 个原 PID＋创建时间实例均已退出，本次根证书当前不在 CurrentUser Root 信任库。

每组 `agent-evidence.json` 记录四个阶段，引用 `flow-evidence.json` 中真实观察 ID。参与程序自行输出的查询／转换／上传步骤标记为测试真值，不进入身份、内容传播或采集认证。

## 关联结论与限制

| 关系 | 本轮证据 | 结论 |
| --- | --- | --- |
| 源文件→A 委派 | 同进程、顺序、登记内容重叠 | Low 来源候选；进程内转换没有逐字节观察 |
| A 委派→B 收到 | 实际管道端点、任务／消息 ID、完整消息及 Native 交接一致 | Medium；跨端局部连接代次仍非直接映射 |
| B 消息→外发 | TLS 中的父消息 ID 与已观察消息匹配，内容匹配另列 | Medium 协议父引用；应用声明不等于字节因果 |
| 外发→源站 | 同层正文哈希、长度与次数核对 | 受控接收已确认；不宣称源站请求 ID 直接传播 |

两进程先空闲启动，再启动 ETW，所以初始进程身份登记属于快照，不能作为实际 ProcessStart。ETW 提供实际文件、网络及退出事件；文件访问和网络连接本身不证明敏感字节已送达。

本轮实际 ETW 包含 15,398 条文件访问、743 条文件读取、322 条网络活动、30 条进程退出；另有 30 条显式登记快照，实际 ProcessStart 为零。快照不纳入 16,493 条实际事件计数。

协议使用独立 task/message/tool-call/attempt 标识，审计只保存标识哈希；每次外发独立记录，重复、冲突或缺失标识不会被强行合并。普通 `/upload` 保持普通外发检测，不转换为 LLM 请求，也不冒充真实模型工具调用。

## 自动回归与工程检查

本轮全量回归记录位于 `runs/cross-agent/20261023-final-checks/`。新测试覆盖严格 JSON 和总正文上限、消息 ID 及重放、两类负例、大于 64 KiB 中文模型样本、原观察引用、健康降级、报告失败、受控启动顺序和日志隐私。

最终全量自动测试 **610 passed，0 failed，0 skipped**，报告 `pytest-final.xml`。其中包含新增验收探针的缺 TLS、重复回执、零 ETW、提前 terminal、丢失、身份错误和错误检测结果反例，避免仅凭探针成功返回判定通过。此前 592 项中间结果保存在 `pytest.xml`，不覆盖历史记录。

`uv lock --check`、`uv pip check`、34 份 Schema 无漂移及 Flow 正式构建依赖检查通过。现有 30 份 Schema 与开发前备份／Git 基线一致。Python wheel 继续只包含 Python 包及元数据；测试输入、证书、运行结果与 Native EXE/DLL 不进入源码白名单或 wheel。

本轮复用了固定 Native 构建并实采 Native I/O、ETW、eCapture；没有重跑原 Codex HTTP/WSS Guard、TCP 门控、WFP、真实浏览器或完整 IDE UI 的独立受控回归，不能用本轮测试数量替代这些场景的新实采结果。原记录继续保留。

## 仍未验收

- 真实 Agent 框架、生成式摘要、改写后只保留语义的敏感信息传播。
- 并发消息、实际重试、管道重连、文件覆盖／替换以及跨采集器故障联动。
- 浏览器、剪贴板、共享内存、远程 IPC、任意业务应用与跨主机委派。
- 应用 B 新的发送前阻断、完整字节级污点追踪和唯一来源证明。

以上边界没有因为 15 组固定实验通过而关闭。当前成果是跨 Agent 受控查询—委派—转换—外发链路的观察和候选传播原型。
