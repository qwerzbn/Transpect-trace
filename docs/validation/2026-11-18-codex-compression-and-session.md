# Codex 同一对话恢复与长文本实测

2026-11-18，在 Windows 11 上以当前用户运行真实 Codex 桌面包 `26.1111.2228.0` 的后端。每场使用独立进程、临时配置、合成令牌和不转发的本机接收端。先提交正常问题，再提交敏感问题，最后在同一对话里继续问正常问题。

| 实际传输 | 敏感轮 | 接收端在恢复轮读到的内容 |
|---|---|---|
| 普通 HTTP | 本地直接拒绝，接收端 0 个连接 | 47,792 字节，有新问题，无历史令牌 |
| zstd HTTP | 本地直接拒绝，接收端 0 个连接 | 线上 16,626 字节，独立解压后 47,792 字节，有新问题，无历史令牌 |
| zstd HTTP，首轮含 256 KiB 正常长文本 | 本地直接拒绝，接收端 0 个连接 | 线上 23,413 字节，解压后 309,882 字节，长文本逐字保留，无历史令牌 |
| WSS，同一对话重复提交相同的令牌 | 两次敏感输入均被拒绝，均无对应的模型帧 | 两次随后的正常消息均获得预设答复。接收端共收到 1 个预热帧、3 个正常请求帧，无 HTTP 回退 |

每个恢复轮都核对原始加密归档中的历史令牌，并把实际接收正文和清理副本逐项或按带密钥摘要比较。客户端能继续对话、接收端能解压、敏感轮没有抵达，是三项分别记录的断言。

## 历史处理

当前轮次命中敏感策略会直接结束。下一轮发出前，系统在同一对话内核对先前被拒条目的内容、位置和轮次。WSS 从增量帧切回完整历史时，额外核对唯一消息 ID、整条消息摘要和片段位置。只有出现新的正常用户消息，且能唯一确定旧敏感条目时，才对出站副本中的历史做替换。

清理后的完整正文再次解析并检查。在线传输为 zstd 时，放行副本还需编码为等长的单个合规帧，并独立验证解压结果。无法核对历史、长度或时限时会拒绝该请求。内存中的拒绝记录随守护器重启而失效。

## 减少长文本重复检查

1. 按 65,536 个字符扫描长文本，相邻块重叠 15 个字符。先筛出可能出现的规则特征，例如某类凭据使用的前缀。
2. 在同一次检查中为原文及解码文本复用相同块的预筛结果。末尾只有一个 URL 转义时，两种文本共有的大段开头只需计算一次。
3. 出现候选特征后，规则仍在完整文本上匹配并校验，跨块的凭据仍可识别。会话内的条目缓存另行处理已经检查过的历史。此次优化使用本地规则和缓存。

每组约 2.2 MB 的正常正文，新旧引擎在同一电脑交替运行各五次。下表为纯内容检查耗时中位数，单位为毫秒。

| 正常输入 | 优化前 | 本次发布代码 |
|---|---:|---:|
| 重复的发布说明 | 439 | 25 |
| 同样的说明，末尾有一处 URL 转义 | 1,132 | 40 |
| 各块内容不同，中段有一处 URL 转义 | 1,187 | 95 |

优化后的 15 次长文本检查均放行。发布测试集的 41 个正常样本全部放行，44 个敏感样本全部拒绝，动作与整理前一致。CI 日志和转义赋值这两个用例使用重新生成的合成凭据，其命中的规则明细随测试值变化。

发布工作树全量运行 2,328 项测试，2,320 项通过，8 项因缺少特定旧版后端、可选 Office 库或 Native 测试程序而跳过，失败 0 项。另行检查了 42 份协议 schema、615 个清单文件和 Python wheel 的内容。执行默认 Windows 启动命令后，原有监视窗与两个守护器均在线。
