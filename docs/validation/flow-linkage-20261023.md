## 发现与修复

- 复杂探针最初依赖管理员进程默认编码，CP936 写入导致 UTF-8 参与程序失败。现已显式 UTF-8，并有默认编码反例测试。
- 管道重连时只统计有正文的代次，可能遗漏空实例；现在同时记录真实连接代次证据。
- 文件读取期间改写检查原先依赖内容候选，可能遗漏没有相同内容的写入。现在独立检查重叠操作、写范围及版本不确定性。
- 关联后段才发现歧义时，早先生成的高等级关系没有回溯降级。现在对受影响范围统一降低；只有缺上游读取而局部交接完整时仍保留局部事实。
- 验收探针增加 TLS 来源、健康、实际 ETW、回执格式、消息冲突、并发业务时间和缺失证据的反例，不能只凭状态字段变绿。
- Native 审计管道存在真实早关闭竞态：客户端 WriteFile 成功并立即关闭，服务端 ConnectNamedPipe 返回 232，可能漏帧而写端 dropped=0。已精确复现并新增 `FIO1-ACK1`。

ACK 由身份核验和完整帧处理完成后的采集器发出，独立 Native 工作线程有界等待；不在被观察的应用 I/O 线程等待，也不是策略门控。缺 ACK、错误 ACK 均记录丢失和降级，FIO1 事件帧保持不变。新产物位于 `build/flow-linkage/`，旧 `build/flow/` 保留 legacy 语义，不被默认为已获得 ACK 可靠性。

ACK 组件另有真实 120 次 scoped I/O、362 个连续帧含 ready／terminal 验证；故意缺失与错误 ACK 均产生 lost=1、degraded，应用线程未因审计确认等待。独立组件证据位于 `runs/flow-audit-ack/20261023-160456/`。
