# Codex 桌面端 DLP 技术方案

整体数据流：

~~~text
Codex 客户端（codex.exe app-server）
  ├─ 本地 Hook（模型请求发送点 HTTP / WSS · 工具执行点）
  │    └─ Native 组件 ──命名管道──> 本地门控服务
  │         ├─ 解析请求条目 → 加密归档 → 内容识别与工具动作策略
  │         ├─ 返回放行或拒绝决定
  │         └─ 写入决策审计与 ETW 关联事件
  └─ Codex 子进程 ──进程 / 文件 / 网络事件──> ETW 采集器
                                                  └─ 行为关联与审计报告
~~~

## 1. 采集层：本地 Hook

采集层不使用 Codex 内置 Hook，也不经过系统代理。Native 组件以 DLL 形式加载到 Codex 本地后端 `codex.exe app-server`，在进程内挂钩模型请求发送函数和工具执行入口，在内容离开进程或工具启动之前取得待检数据。

| 挂钩点 | 触发时机 | 采集内容 |
|---|---|---|
| HTTP 模型请求发送点 | 请求正文序列化完成后、发送前 | 完整请求正文 |
| WSS 模型请求发送点 | `response.create` 帧发送前 | 完整请求正文 |
| 工具执行点 | 工具进程创建前 | 工具名、命令行、工作目录及调用参数 |

模型请求正文即客户端实际上行的内容，包含用户输入、系统与项目指令（含 `AGENTS.md`）、历史消息、工具调用记录、工具结果及附件。门控按 Responses 请求结构将正文拆分为条目，按类别提取文本；对于结构化工具参数和结果，递归检查字符串值及键名。界面对话、Agent 后续轮次和客户端后台请求经过同一发送点，采集不区分请求来源。

注入器在加载前核对客户端版本、可执行文件 SHA-256 及挂钩函数入口字节，身份不符时不加载。客户端对 HTTP 正文做 zstd 压缩时，门控解压还原后再检查；同一会话内已判定的条目按带密钥摘要缓存，长会话只检查新增条目。

Native 组件通过命名管道调用常驻门控服务，服务端校验管道客户端的进程 ID 与用户 SID。判定超时、管道断开或回复格式异常时，Native 组件拒绝该次请求。

## 2. 内容识别层

内容识别在本地执行，不向云端检测服务发送待检内容。引擎同时检查原文、解码内容和规范化内容。规范化包括 Unicode 宽度折叠、不可见字符处理及常见 Shell、JSON 转义还原。

识别策略由四层组成：

1. **规则与校验：**识别密钥、令牌、私钥、带密码的连接串及个人信息，并对银行卡、身份证等执行格式校验；上下文词用于调整弱规则的证据分数。
2. **熵分析：**检查长字符串的字符分布；高熵命中与凭据上下文共同出现时提高分数，孤立的哈希类字符串只作提示。
3. **EDM 精确匹配：**对登记的客户和员工记录逐字段计算 HMAC-SHA256；同一记录命中多个字段时提高置信度。
4. **文档与源码指纹：**将登记内容切分为片段并计算指纹，按片段数量和覆盖率识别内部资料。

引擎按敏感类别用 noisy-OR 汇总证据，取最高分作为判定：

| 最高分 | 判定 |
|---|---|
| ≥ 0.50 | BLOCK |
| 其他 | ALLOW |

扫描超时、内容无法检查或引擎异常时按拒绝处理。工具调用还经过动作策略，检查敏感文件访问、对外传输和门控配置修改等行为。

## 3. 拦截层

门控将判定经命名管道返回 Native 组件，由 Native 组件在对应挂钩点执行：

| 场景 | 拦截动作 | 效果 |
|---|---|---|
| 敏感输入或客户端注入内容 | 在发送点拒绝模型请求 | 请求不上行；本轮以策略错误结束，客户端不重试 |
| 敏感工具调用 | 在工具执行点拒绝进程创建 | 工具不执行；Agent 收到拒绝理由 |
| 敏感工具结果 | 在发送点拒绝携带该结果的后续请求 | 工具结果不进入模型请求 |

判定只有放行和拒绝两种结果：ALLOW 放行，BLOCK 拒绝。拒绝以客户端原生的请求错误返回，不调用原发送函数，也不触发客户端重试。

## 4. 审计与行为关联

审计层由同步门控审计和异步 ETW 行为审计组成。门控审计记录内容判定，ETW 审计记录 Codex 子进程的文件与网络活动；关联器将两类证据组织成工具调用时间线。实时拦截由本地 Hook 执行，ETW 提供行为证据。

### 4.1 门控决策审计

每次挂钩点判定生成结构化记录，包含 Native 请求 ID、挂钩点、会话 ID、轮次 ID、工具调用 ID、条目类别与位置、判定、命中规则、处理耗时及加密归档记录 ID。模型请求的完整正文作为一条记录归档，各条目以位置和带密钥摘要引用该记录。待检正文进入 AES-GCM 加密归档，密钥由 Windows DPAPI 保护；审计记录不写入正文、凭据或认证头。需要比较内容一致性时使用带密钥的摘要。

允许决定在归档和审计持久化后返回。审计写入采用进程间锁与大小轮转；写入失败时返回拒绝。门控同时发布自定义 TraceLogging 事件，作为 ETW 时间轴上的关联锚点。

### 4.2 ETW 进程、文件与网络审计

独立采集器启动实时 ETW 会话，订阅 Windows 内核的三类事件，并解码为统一的行为记录：

| ETW provider | 采集信息 | 审计用途 |
|---|---|---|
| Microsoft-Windows-Kernel-Process | 进程启动、退出、父子关系及创建时间 | 维护以 Codex 为根的子进程树 |
| Microsoft-Windows-Kernel-File | 文件打开、读取、写入及文件对象标识 | 关联文件对象与路径，区分打开和读取操作 |
| Microsoft-Windows-Kernel-Network | TCP / UDP 通信、远端 IP 和端口 | 记录子进程通信的地址与时间 |

进程实例以 PID 和创建时间共同标识。采集器用文件对象标识恢复路径，将读取、写入事件归到对应进程；网络事件按进程汇总协议、远端 IP、端口和时间。文件正文与网络载荷不写入 ETW 审计。

### 4.3 工具调用关联

每次工具调用以会话 ID、轮次 ID 和工具调用 ID 建立执行区间。工具执行点在进程创建时记录工具调用 ID 与进程实例的映射。关联器沿 ETW 子进程树汇总文件及网络事件，形成“工具调用 → 子进程 → 文件读取 / 网络通信 → 门控判定”的可检索时间线。

审计报告保留原始事件 ID、进程身份、时间依据及采集丢失计数，并按工具调用逐次核对门控记录与行为事件。报告展示工具读取的文件、访问的远端地址、内容识别结果和最终决定。

## 5. 本地 Hook 演示与验收

本节定义桌面端演示的目标效果与验收证据。演示在固定版本的 Codex 桌面端运行，不启用内置 Hook 和系统代理。本地 Hook 在工具执行点和模型请求发送点门控，两处使用同一策略版本，判定与审计记录按会话、轮次和请求关联。测试工作区放置含合成令牌的文件和 `AGENTS.md`；受控接收端只监听本机回环地址。

### 5.1 完整场景

| 场景 | 测试输入 | 本地 Hook 判定 | 预期验收结果 |
|---|---|---|---|
| 正常对话 | 普通出行咨询 | 发送点放行完整请求 | 模型正常回复；归档正文与捕获正文摘要一致 |
| 输入含凭据 | 用户粘贴合成 GitHub 令牌 | 发送点识别用户输入中的令牌，发送前拒绝 | 请求未上行；客户端显示策略拒绝，不重试 |
| 输入含个人信息 | 姓名、身份证号、银行卡号、手机号及地址 | 发送点经格式校验与上下文识别后拒绝 | 请求未上行；客户端显示策略拒绝 |
| 工具结果含凭据 | 要求 Agent 读取工作区文件并原样返回，文件含合成令牌 | 首次请求放行；工具执行后，携带结果的后续请求被拒 | 文件正文未进入模型请求 |
| 编码外发 | 要求 Agent 将该文件 base64 编码后返回 | 发送点解码工具结果，识别令牌后拒绝 | 编码结果未进入模型请求 |
| 工具直接外发 | 要求 Agent 用 curl 上传该文件 | 工具执行点识别敏感文件上传，在进程创建前拒绝 | curl 未执行；受控接收端未收到数据 |
| 客户端注入内容 | 在含合成令牌 `AGENTS.md` 的目录下发起对话 | 发送点识别项目指令中的令牌并拒绝 | 令牌未随项目指令上行 |
| 后台请求 | 客户端为当前项目生成建议，请求汇总近期会话内容 | 发送点识别汇总内容中的令牌与个人信息并拒绝 | 已拒绝的敏感内容未经后台请求上行 |

工具执行点已经拒绝时，不形成携带该工具结果的后续请求；工具执行点放行时，发送点对后续请求作发送前复核。每个场景以 Native 判定、加密归档回读、客户端日志及受控接收端记录共同验收，而不以客户端提示代替外发证据。

### 5.2 逐次指标与审计

每次运行生成一条场景记录，包含样本 ID、会话与轮次 ID、Native 请求 ID、挂钩点、判定与命中规则、正文长度、带密钥摘要、工具是否执行及受控接收端接收次数。受控接收端先以无害发送完成可达性对照，再核对敏感样本的接收结果。审计报告沿工具调用关联 ETW 进程、文件和网络事件，展示子进程实际读取的文件、连接的地址与最终门控动作。

时延分别记录 Native 组件从捕获到收到决定的耗时，以及用户提交到最终结果的端到端耗时。报告逐次列出耗时，再汇总 P50、P95、P99。阻断率以有效的带标签尝试为分母，只有敏感内容在离开进程或工具启动前被拒绝、且受控接收端未收到敏感字节时才计为成功，同时报告良性请求放行率。
