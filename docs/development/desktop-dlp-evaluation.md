# 桌面端 DLP 内容识别评测（本地离线判定）

本评测只调用本地四层内容识别引擎，**不启动 Codex 桌面端，也不验证实际发送前 Hook、WFP 或源站零字节**。公开语料是合成 PII；文件夹具也是脚本生成的假密钥、假员工记录和假内部文档。样本文本不写入报告，也不发送给云端分类器。

## 语料与运行

| 语料 | 固定修订 | 文件 SHA-256 | 本次行数 |
| --- | --- | --- | ---: |
| [Gretel PII Masking 英文 test](https://huggingface.co/datasets/gretelai/gretel-pii-masking-en-v1) | `e06eb1499ca8d54470f085021cd8e54f9efac7fd` | `c89a6bffa838edb0f2fc6686bf35da4930944519ac97308b0b6e32298594b5b1` | 5,000 |
| [PII Bench ZH 正式文本](https://huggingface.co/datasets/wan9yu/pii-bench-zh) | `c350b94897af668517ff5de237d89f2ce2eaa6f0` | `bcaa54909fd69c6737b8e442c4d740ce1bf5b95b7d4af70b2f2692010e1ff7a5` | 5,000 |
| [PII Bench ZH 聊天文本](https://huggingface.co/datasets/wan9yu/pii-bench-zh) | `c350b94897af668517ff5de237d89f2ce2eaa6f0` | `4ddacd78dfac49b723032de5e1c29c432a44049245e03a8ea960c86bbf3b765c` | 3,000 |

语料首次运行时下载到 `runs/desktop-dlp-datasets/`，之后按上述 SHA-256 核验；哈希不符即停止。DuckDB 固定为 `2.0.0`，运行依赖见项目锁文件。全量命令：

```powershell
uv run --no-sync --with duckdb==2.0.0 python scripts/evaluate_desktop_dlp_datasets.py --per-dataset 0
```

生成的详细报告在 `runs/desktop-dlp-datasets/report.json`。默认命令读取三套固定文件的全部 13,000 行；若要快速回归，可显式传入 `--per-dataset 500`，以种子 `2026-11-04` 和行 ID 的哈希在每套语料中固定抽样。默认运行不再以 500 行结果覆盖全量报告。上述两个中文文件分别是发布方标注的正式文本和带噪声聊天子集，不能合并成一个未分层结果。下载文件在进入缓存前、复用缓存时都必须通过固定大小和 SHA-256 核验。

## 结果与口径

| 语料 | BLOCK | REVIEW | ALLOW | 脱敏副本 ALLOW | 原始文本判定 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Gretel 英文 | 1,170 | 589 | 3,241 | 4,975 / 5,000 | 0.128 ms |
| 中文正式文本 | 2,652 | 1,292 | 1,056 | 5,000 / 5,000 | 0.044 ms |
| 中文聊天文本 | 638 | 1,147 | 1,215 | 3,000 / 3,000 | 0.038 ms |

按既定策略，未来桌面门控遇到 `REVIEW` 应拒绝；本评测不证明门控已经部署。语料含姓名、邮箱、电话等强弱不同的实体，不能把每个 `ALLOW` 都算作漏检，也不能把上表的拒绝比例称为准确率或召回率。脱敏副本通过替换标注实体生成；Gretel 副本仍有 18 条 `REVIEW`、7 条 `BLOCK`，约占 0.5%，两个中文副本均全部 `ALLOW`。未标注的敏感内容仍可能留在副本中，因此这只是**误报诊断**，不是经人工核验的误报率。耗时为一次实测，会随机器负载变化，且仅测内容引擎，不含采集、加密落盘、IPC 和发送。报告 `1.1` 显式标记 `blind_holdout=false`、`policy_truth_available_for_public_corpora=false`、`live_enforcement_verified=false`，夹具行使用 `policy_would_deny`，脱敏副本使用 `redacted_proxy_decisions`，不把离线计算写成实际阻断或已验证真阴性。

下表按语料的实体标注汇总**含该标注的整行文本被门控拒绝的比例**。一行可同时标注多类实体，拒绝可能由其中另一类触发，因此这些数字不是逐实体检出率，也不能相加。

另以明确标注期望动作的合成夹具测试文本、PDF，以及真实 OOXML 结构的 DOCX、XLSX 和 PPTX。混淆矩阵：期望 `BLOCK` 的 13 项中，12 项返回 `BLOCK`，1 项返回 `ALLOW`；期望 `ALLOW` 的 9 项全部放行。漏检项是**仅保留含义、改写全部字面内容的内部文档**，四层词面/结构识别无法稳定抓到。未知二进制格式和无可提取文字的 PDF 均因无法完整检查而拒绝，这两项未算入内容识别检出率。

Office 夹具使用固定哈希的合成模板生成：DOCX 经 `python-docx 1.2.0`、XLSX 经 `openpyxl 3.1.5`、PPTX 经 `PptxGenJS 4.0.1` 建立；替换文本后分别用文档库重新打开，PPTX 还通过 Office 包结构校验。DOCX 模板移除了默认缩略图和自定义 XML，并同步删除相关关系；当前支持范围是**可提取文字、无嵌入媒体的文件**。媒体、缩略图或其他无法完整检查的部件仍按拒绝处理。这些各一份的合成 Office 文件证明了这三条具体解析路径，不能代替真实业务文件的兼容性测试。模板 SHA-256 在评测脚本中固定，ZIP 条目时间戳固定；两次全量复跑的判定、规则编号、样本哈希和语料计数一致，耗时字段因机器负载而变化。

本次公开语料的汇总结果曾用于修正中文数字前的匹配边界，并补充身份证、银行卡和护照上下文规则；因此它属于**开发诊断数据**，不能宣称为未见过的盲测集。公开语料的实体类型也不能直接映射成 `ALLOW/REVIEW/BLOCK` 真值：例如单独姓名、联系方式、证件号在不同策略和上下文下可能采取不同动作。

独立策略标签可以建立，但应先冻结检测器和企业策略，再从**未用于规则调整**的语料中按预先固定的种子抽样，纳入无敏感内容、边界样本和改写样本；标注者不看检测结果，分别给出期望动作与依据，对分歧进行复核并保留标签版本。完成后才能计算策略级混淆矩阵、敏感样本漏放率和良性样本误拒率。当前报告里的合成夹具由开发者制作，虽有明确期望动作，也不构成独立盲测。发送前 Hook、源站零字节及 Agent 工具外发须另行验证。
